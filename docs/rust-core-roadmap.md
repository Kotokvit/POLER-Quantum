# Rust Core Roadmap — архитектурное решение

> **Статус:** решение владельца, зафиксировано 2026-08-27. Разворачивается после v1.0.0 как v2.x-линия. Python-реализация (`poler_quantum/`) остаётся reference-ом и инструментом обучения.

## 1. Решение

Четыре пункта, дословно из сессии владельца:

1. **Продакшн-симулятор НЕ обязан работать через qiskit** или другие программы для симуляции квантовых — qiskit и другие библиотеки это просто **инструменты для разработки математики**.
2. **Всё пишется на Rust** — фазовый энкодер, statevector-симулятор, Born sampling, McWeeny, операторы `(D, J, Π_Λ)`.
3. **Обучать будем Born + Python, когда нужно.** Rust — инференс и сжатие; Python — исследовательская петля обучения поверх того же формата состояния.
4. **Обучение будет полностью через интернет.** Программа для этого уже написана — см. poler-engine `docs/future-streaming-archives.md` (Zero-Storage Streaming Archives): потоковое чтение архивов из сети в память, ε-фильтрация и POLER[Ψ]-сэмплирование батчей без хранения датасета на диске.

## 4. Milestones

* **RQ1 — `poler-quantum-rs`: фазовый энкодер + statevector.**
  Чистый Rust-крейт: `Ry(arccos p_i)`-энкодинг, entanglement-цепь (CX/CZ), statevector-симулятор, Born sampling с детерминированными сидами. Ноль внешних квант-зависимостей. Паритет с `quantum/ansatz.py` по распределениям (χ²-тест на фиксированных сидах).
  **Старт положен (2026-08-27):** репозиторий [POLER-Quantum-RS](https://github.com/Kotokvit/POLER-Quantum-RS) создан — крейт `pqw` v0.1.0 (контейнер `.poler`/`.pqw`, zero-dependency, mmap zero-copy, 66 тестов + 2 doc-теста). faer/SIMD-ядро — следующий слой поверх этого контейнера.
* **RQ2 — McWeeny purification. ✅ ВЫПОЛНЕН в Python (v1.1.0, 2026-08-27).**
  `P_new = 3P² − 2P³` в `poler_quantum/core/purification.py`: квадратичная сходимость (8-битная сетка: 6.3e-3 → 9.4e-9 за 2 итерации), сохранение ранга, честные ограничения (дрейф подпространства ~ коррупция). Адаптивная ε-глубина — `quantum/compression.py`: фон на тритах, спайк разворачивает сетку до 256 уровней за один шаг; измерено RMSE 0.0739 (2.23 бита) vs 0.0740 (полная точность). Rust-порт уезжает вместе с RQ1.
* **RQ3 — ε-adaptive bit-depth.**
  Мапа `ε(W_t)` → глубина анзаца: фон — 1–2 кубита/триты, спайк — полный `J = A − Aᵀ` разворот. Бенчмарк «сжатие vs качество трекинга» из `benchmark/`. Скалярная глубина состояния закрыта в v1.1.0 (`AdaptiveDepth`); остаётся топологическая — по координатам/модулям и генератор-уровневое сжатие матриц (не входов).
* **RQ4 — паритет Rust ↔ Python/qiskit.**
  Cross-validation: Rust statevector vs Aer на одинаковых схемах; расхождение < 1e-12 на малых n. Qiskit окончательно уходит в роль «инструмент разработки математики».
* **RQ5 — петля обучения Born + Python.**
  Gym-интерфейс поверх Rust-ядра (FFI/CLI), ε-награда, потоковые задачи. Данные — через RQ6.
* **RQ6 — обучение из интернета.**
  Интеграция с poler-engine Zero-Storage Streaming: батчи из сети → ε-фильтр → POLER[Ψ] сэмплирование → обучающая петля RQ5. Ноль терабайт на диске.

## 5. Формат состояния (контракт между Rust и Python)

Компактный бинарный формат, одинаковый для инференса и обучения:

* заголовок: размерность `d`, режим анзаца (A/B/C), счётчик такта `t`;
* вектор `p ∈ [-1,1]^d` в f32/f16 (глубина — по §3 dynamic-quantization.md);
* метаданные резонанса: `R_t`, режим (novelty/habit), `ε̂`;
* опционально: сжатые веса `J = A − Aᵀ` (антисимметричный — храним только верхний треугольник, ×2 экономия).

Формат стабилен с RQ1, версионируется. Любой узел POLER Mesh (exec, engine) может исполнить состояние без переквантования.

> **Статус (2026-08-27):** первый слой контейнера реализован — крейт [`pqw` v0.1.0](https://github.com/Kotokvit/POLER-Quantum-RS)
> (репозиторий POLER-Quantum-RS): zero-dependency формат `.poler`/`.pqw` — фазовые триты `{−1, 0, +1}` + 6-битная
> кривизна, sparse LENS-топология (u16/u32), mmap zero-copy, целостность SHA-256/FNV-1a, McWeeny-инвариант
> `P² = P` в заголовке. Байто-точная спецификация: `docs/pqw-format.md` того репозитория. Поля режима анзаца,
> такта `t`, `R_t` и `J = A − Aᵀ` — план v2 поверх стабильного заголовка v1.
